title: 投稿指南
description: 双轨制投稿——平台内发帖是默认轨,门面站 PR 是精选轨。
---

X-SIA 的内容分两条轨,分别对应两种不同的内容生产方式。

## 内容分流原则

判断一篇内容该走哪条轨,看两个问题:

- 谁写?只有少数干事写,还是所有成员都能写?
- 怎么发布?需要走 git 提交和审核,还是应该发了就能立刻看见?

编辑型内容（少数人写、要过审、追求 SEO 和长期沉淀)进门面站;用户生成内容（多数人写、即时发布、需要运行时的鉴权和审核)进应用内的平台发帖。

## 轨道一:平台内发帖（默认轨)

在应用里登录后直接发帖,面向全体成员。这是**默认**的分享渠道——日常的想法、活动感想、求助、讨论都应该发在这里。

发帖是运行时行为、存在数据库里,不会触发门面站重新构建,因此不需要任何 git 操作。这也是为什么门面站的技术选型（fumadocs）**不**用来承载这类内容——fumadocs 是构建时的文件系统模型,普通成员发帖不可能每次都触发一次网站重新构建。

论坛类功能会在后续迭代逐步开放,开放前的公告以群里通知为准。

## 轨道二:门面站 PR 投稿（精选轨)

如果你想写一篇更完整、更适合长期沉淀、面向社团外部读者的文章——比如技术分享、活动复盘、社团理念——欢迎往门面站的 `blog/` 目录提 PR。这条轨面向所有想认真写一篇文章的成员开放,不限于干事。

具体的 frontmatter 格式、图片存放位置、PR 标题规范和审核流程,见仓库根目录（`apps/site/`）下的 [`CONTRIBUTING.md`](https://github.com/x-sia-club/x-sia/blob/main/apps/site/CONTRIBUTING.md)。

简要流程:

1. Fork 仓库,在 `apps/site/content/blog/` 下新建一个 `.mdx` 文件。
2. 按规范填写 frontmatter（`title`、`description`、`author`、`date`),图片放进 `apps/site/public/blog/<slug>/`。
3. 提交 PR,标题按约定格式书写。
4. 干事负责 review,承诺 **7 天内**给出回复（合并、要求修改,或说明不合适的原因)。

两条轨没有优劣之分——想法先发平台,想认真写一篇能被检索、能被引用的文章,再考虑 PR。
