# C++：值、容器与资源所有权

> 先修：变量、循环、函数的概念；可以先读 C 入门，但不要求先掌握全部 C。环境：C++20 与支持该标准的编译器。本章目标：用标准容器和明确所有权编写小程序，理解对象构造、销毁、复制与移动。

## 2.1 不从手写内存分配开始

C++ 提供与机器接近的控制能力，也提供表达容器、算法和资源生命周期的抽象。初学者不应把“学习 C++”等同于“先到处写 new 和 delete”。优先使用 `std::string`、`std::vector` 等管理自身资源的类型。

```cpp
#include <iostream>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> samples{2, 4, 9};
    if (samples.empty()) {
        std::cerr << "no samples\n";
        return 1;
    }
    double total = std::accumulate(samples.begin(), samples.end(), 0.0);
    std::cout << "mean=" << total / samples.size() << '\n';
}
```

用 `c++ -std=c++20 -Wall -Wextra -Wpedantic main.cpp -o demo` 编译，在合适的终端运行。输出应为 mean=5。初始累加值 `0.0` 使这里的累加类型为 double，若用 0 则会使用整数累加并改变溢出风险。

## 2.2 对象同时包含状态与行为

一个类可以把状态和保持其有效的操作放在一起。构造函数建立对象应满足的不变量，析构函数在对象生命周期结束时释放其拥有的资源。

例如文件对象除了路径，还代表已打开的操作系统句柄；互斥锁守卫代表已经取得的锁。RAII 的核心是把资源所有权绑定到对象生命周期，而不是仅指“把变量放在栈上”。对象也可能位于堆上，只要所有权链正确，析构仍能发挥作用。

![图 2-1：作用域中构造资源所有者，正常退出或异常展开时销毁；借用者不负责释放同一资源。](asset:languages-cpp)

智能指针是所有权工具。`std::unique_ptr<T>` 表示独占拥有动态对象；`std::shared_ptr<T>` 表示共享所有权并维护引用计数。后者不是默认更安全：循环引用、额外成本和线程间对象访问仍需处理。

## 2.3 值、引用与指针的不同契约

按值传参通常让函数取得自己的对象；引用表示别名；指针可表达某些可空访问。选择接口时应该先问“要复制、借用、修改还是转移所有权”。

```cpp
#include <string>

std::size_t length_of(const std::string& text) {
    return text.size();
}

void add_suffix(std::string& text) {
    text += ".txt";
}
```

第一个函数通过常量引用读取，不复制字符串；第二个函数明确修改调用者的字符串。返回指向局部对象的引用同样会悬空。`std::string_view` 是不拥有字符数据的视图，长度信息并不能让它延长源字符串的生命。

`const` 是接口约束的一部分，不是跨线程同步手段。引用所指对象也必须满足寿命、并发和有效范围条件。

## 2.4 vector 的长度、容量与迭代器失效

vector 的 size 是已构造元素数，capacity 是当前分配可容纳的元素数。`reserve(n)` 请求容量，不把 size 改成 n；`resize(n)` 改变元素数。混淆二者会导致在尚不存在的元素上进行访问。

若底层需要重新分配，原来的指针、引用与迭代器可能失效。保存 `&v[0]` 后继续向 v 添加元素，不能假定地址不变。接口越接近底层，就越需要清楚失效规则。

在采用几何扩容的典型分析模型中，容量翻倍时搬移量形成 $1+2+4+\cdots+2^k<2^{k+1}$，因此 N 次追加的总搬移量为 $O(N)$，单次追加为摊还常数级。但某一次扩容仍可能是线性的，且标准不规定某个固定扩容因子。

## 2.5 复制、移动与“被移动后的对象”

复制通常创建新的值；移动允许把资源转交给另一个对象，但实际行为由类型定义。`std::move` 本身是转换表达式类别的工具，不必然执行资源搬运。它使后续调用有机会选择移动构造或移动赋值。

标准库许多类型在被移动后处于有效但未指定状态，应依据具体保证使用；不能普遍断言“移动后的字符串必定为空”。自定义类如果手动管理资源，则复制与移动语义必须一起设计。

Rule of Zero 建议尽量由标准资源成员管理生命周期，从而避免自己编写析构、复制和移动操作。这不是偷懒，而是减少必须亲自维护的不变量。

## 2.6 异常与工程组织

异常表示一种失败传播方式。异常安全需要区分基本保证、强保证与不抛出保证；有析构函数并不自动让业务操作可回滚。析构期间抛异常尤其危险，应避免把正常资源释放依赖于可能失败的复杂业务。

开始组织项目时，把接口和实现分开，保持头文件最小依赖。编译选项、测试目标和依赖版本应由构建系统记录。不要把“单文件在 IDE 中运行成功”当作跨平台库已经交付。

后续路线包括重载、模板与概念、标准算法、范围、异常安全、并发、性能分析和库设计。C++ 的“精通”更依赖选择正确抽象，而不是记住尽可能多的语法。

## 练习与解题提示

1. `std::vector<int> v; v.reserve(10);` 后 size 是多少？可否写 `v[0] = 1`？
2. 为什么返回局部 string 对象的 string_view 可能悬空？
3. std::move 是否保证调用移动构造？

**提示与答案：** 1. 仍为 0，不能访问不存在的第一个元素；可用 push_back 或先 resize。2. view 不拥有字符，局部字符串销毁后底层存储失效。3. 不保证，取决于目标类型和重载选择，也可能复制。

## 小结与参考

把 C++ 当作“能够精确表达所有权与值语义的语言”，而不只是带类的 C。让资源管理、接口契约与测试共同构成可靠性。

- [LearnCpp](https://www.learncpp.com/)：适合按顺序学习的英文教程，从工具链、变量逐步进入对象和语义。
- [cppreference 中文参考](https://zh.cppreference.com/w/cpp)：用于核对标准版本、容器失效规则和函数要求；参考手册不是逐章课程。
- [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)：围绕资源、接口与并发的工程规则，阅读时结合具体问题。
- [现代 C++ 教程](https://changkun.de/modern-cpp/zh-cn/)：中文进阶材料，适合已有基础后对照现代特性；本页仅链接，不转载原图。
