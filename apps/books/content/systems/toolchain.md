# 编译、链接与 ABI

> 先修：[数据与指令](book:systems/representation)、基础 C。目标：解释源码如何成为可装载程序，定位编译、链接、装载和运行时四类问题。命令以 GCC 与 GNU Binutils 的 Linux 环境为例。

## 2.1 一个编译命令包含多道工序

预处理处理头文件包含、宏和条件编译；编译把翻译单元转成目标相关表示；汇编把汇编文本编码为目标文件；链接解析符号、布局段并处理重定位。现实编译器可能在内存中连接阶段，LTO 也会改变阶段边界，但这些职责仍有解释力。

![图 2-1：源文件分别经过预处理、编译和汇编生成目标文件，链接器结合库与布局生成 ELF，装载器再建立进程映像。](asset:systems-toolchain)

```bash
gcc -E main.c -o main.i
gcc -S main.c -o main.s
gcc -c main.c -o main.o
gcc main.o helper.o -o demo
```

这些命令会创建或覆盖指定输出文件，应在专用练习目录使用。前三行展示不同停点，不是说必须手动按这个顺序重复处理同一输入。

## 2.2 声明、定义和链接符号

声明告诉编译器某名字的类型和使用方式；定义提供函数体或实际对象。一个头文件中的函数声明可以让 `main.c` 编译通过，但如果链接时没有提供定义所在的目标文件，链接器仍会报告未定义引用。

```c
/* helper.h */
int twice(int x);

/* helper.c */
int twice(int x) { return 2 * x; }

/* main.c */
#include "helper.h"
int main(void) { return twice(3) == 6 ? 0 : 1; }
```

分别保存后编译，`nm main.o` 可以看到对 twice 的未定义引用，`nm helper.o` 可看到其定义。链接器把引用与定义关联起来。

把普通全局变量的定义放进被多个源文件包含的头文件，可能造成重复定义。头文件保护防止一次翻译单元内重复包含，不自动解决跨多个翻译单元的全局定义冲突。

## 2.3 重定位：编译时不知道最终地址怎么办？

编译一个目标文件时，外部函数的最终地址可能未知。目标文件记录占位内容和重定位信息，链接器在布局确定后修正引用；动态链接时部分工作还会推迟到装载或运行期间。

以某类 PC 相对重定位为简化模型，待填值可能形如：

$$
V=S+A-P,
$$

其中 S 为目标符号地址，A 为附加数，P 为重定位位置。具体指令还可能要求缩放、位拆分和范围检查。这个表达式不是所有平台全部重定位的统一公式。

若 S=0x1200、A=0、P=0x1000，差值为 0x200。重定位溢出常意味着指令可编码范围或布局约束不满足，并不等于 C 语法错误。

## 2.4 ABI：函数之间的二进制契约

API 约定源码层如何调用，ABI 约定编译后如何合作：参数放在哪里、返回值在哪里、哪些寄存器由调用者保存、栈如何对齐、符号如何命名、对象如何布局。

以常见 System V AMD64 ABI 的简单整数参数为例，前几个整型参数常使用 RDI、RSI、RDX、RCX、R8、R9。这个规则不能直接套到 Windows x64，也不能套到 Arm；浮点、结构体返回和变参还有更细分类规则。

栈帧常包含保存状态、局部数据和溢出到栈的参数，但优化器可以省略帧指针或让局部变量一直留在寄存器。不要把教学图上的固定栈帧当成每个编译结果的逐字节布局。

调用约定错误可能表现为“链接成功但运行错”：双方对类型大小、浮点传递或结构体布局理解不同，链接器未必能识别全部错误。

## 2.5 静态链接、动态链接与装载

静态链接把需要的部分库代码组合进可执行文件；动态链接通过共享对象在装载或运行时提供实现。动态链接减少某些重复，并允许库独立更新，但引入运行时路径和版本兼容性问题。

Linux 的装载过程根据可执行文件信息建立地址空间，并在需要时启动动态链接器。`main` 并非 ELF 入口的同义词：运行库通常先建立运行环境，再调用 main。

检查不可信文件时应谨慎选择工具；例如对不可信可执行文件使用 `ldd` 存在历史和实现相关风险，优先用 `readelf` 等静态检查方式查看所需共享库信息，不执行来源不明的文件。

```bash
readelf -h demo
readelf -l demo
readelf -d demo
nm main.o
```

这些输出分别回答文件身份、装载布局、动态信息和符号问题，而不是用一条“大而全”的报错猜全部原因。

## 2.6 按阶段排查错误

| 现象 | 首先检查 |
|---|---|
| 头文件找不到 | 包依赖、包含路径和生成步骤 |
| 类型冲突 | 声明一致性与实际包含的头文件 |
| undefined reference | 定义是否编译、是否参与链接、名称和库顺序 |
| 无法执行或格式错误 | 目标 ISA、操作系统和解释器路径 |
| 动态库找不到 | 运行时加载路径与部署依赖 |
| 运行结果错误 | ABI、未定义行为、业务逻辑和输入 |

编译选项应作为项目配置保存，而不是依赖某个终端的历史。固件和服务都需要能追溯到源版本、依赖、目标与构建参数。

## 练习与解题提示

1. 为什么有函数声明仍可能链接失败？
2. `#pragma once` 能否解决多个源文件中的重复全局定义？
3. S=0x2800、A=4、P=0x2000，简化 PC 相对重定位值是多少？

**提示与答案：** 1. 声明不提供实现。2. 不能，它控制单个翻译单元内重复包含。3. 0x804；真实编码还需按目标重定位类型处理。
