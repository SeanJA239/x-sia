# 定时器、中断与共享状态

> 先修：[启动过程](book:embedded/boot)、基础 C。目标：从时钟与计数器推导周期，区分事件发生、中断响应和任务完成，并分析共享状态风险。

## 3.1 先找到时钟，再计算周期

CPU 主频不一定等于定时器输入时钟。STM32 不同总线分频、定时器倍频规则与时钟源选择会影响 $f_{tim}$，必须根据具体时钟树推导，不能复制某块板的一个数字。

在典型向上计数、边沿对齐、每次溢出产生更新的简化模型中，预分频寄存器 PSC 对应除数 $PSC+1$，自动重装 ARR 对应从 0 到 ARR 共 $ARR+1$ 个计数：

$$
f_{update}=\frac{f_{tim}}{(PSC+1)(ARR+1)}.
$$

设已确认 $f_{tim}=84\,\mathrm{MHz}$，取 PSC=83，计数频率为 1 MHz；ARR=999 时，更新频率为 1 kHz。中心对齐、重复计数器、外部时钟和特殊触发模式需要不同公式。

## 3.2 PWM 的频率、占空比与分辨率

在明确的边沿对齐、有效电平规则下，占空比可近似写为：

$$
D\approx\frac{CCR}{ARR+1}.
$$

ARR=999、CCR=250 时约为 25%。端点与输出比较模式需查参考手册；不是所有配置都能直接照搬这个表达式。

当输入时钟固定，提高 PWM 频率通常减少每周期计数格数，降低占空比分辨率。格数 $N=ARR+1$ 的等效位数约为 $\log_2N$。1000 格约为 9.97 位，不是因为寄存器是 16 位就永远有 16 位 PWM 分辨率。

占空比平均值能用于某些慢负载，但开关损耗、滤波、负载动态和电磁兼容不能用平均电压一项替代。

## 3.3 事件、中断挂起与响应延迟

外设事件发生后设置状态，中断控制器在允许条件下请求处理器响应。若中断被屏蔽、存在更高优先级处理或处理器正在完成特定操作，响应会延后。外设事件时间、中断入口时间、任务处理完成时间是三个不同时间点。

定义事件发生到处理开始的延迟为 $L$，处理时间为 $C$，需要在截止时间 $D$ 前完成，则必要检查之一是：

$$
L+C\leq D.
$$

这个不等式本身不是完整可调度性证明；$L$ 和 $C$ 应取适当的最坏界，包含屏蔽、嵌套、总线与存储等待，而不是只取平均示波器读数。

Cortex-M 的优先级数值通常越小优先级越高，但实现的有效位数、分组和 RTOS 使用约定仍需要核对。不要把应用层“优先级 10 比 1 高”的习惯直接搬来。

## 3.4 ISR 应完成什么，不应完成什么？

中断服务例程通常完成读取必要状态、按规定清除来源、保存少量数据、通知主循环或任务。耗时格式化、阻塞 I/O 和无界循环会延长其他工作等待时间。

清除标志也有硬件语义：有些位写 1 清除，有些按读取序列清除。对“写 1 清除”寄存器使用通用读改写，可能误清其他事件。因此寄存器访问必须依据手册，不能把所有寄存器看成普通 RAM 变量。

DMA 能把连续搬运交给硬件，但 CPU 仍需处理缓冲区所有权、完成边界与溢出。在带数据缓存的器件上，还需考虑 DMA 与缓存一致性；不能从 Cortex-M4 的一个例子推断所有 Cortex-M 都相同。

## 3.5 volatile 不提供互斥和原子性

`volatile` 用于告诉编译器某对象的访问具有特殊可观察意义，常用于 MMIO 和某些平台规定的异步共享对象。但它不保证一组操作原子，也不提供通用的线程同步与跨核内存顺序。

```c
/* 反例：即使声明 volatile，读-加-写仍可能被打断。 */
volatile unsigned counter;
void task_step(void) {
    counter++;
}
```

`counter++` 可能分成读取、加一、写回。若中断在读取与写回之间也增加 counter，主循环会覆盖那次更新。具体处理方式包括极短临界区、平台支持的原子操作，或者让计数只由一个执行上下文写入。

不能无条件在 ISR 中使用任意 C 原子库函数：某些宽度的原子可能通过锁实现，不适合中断。需确认 lock-free 能力、对齐、内存顺序和目标工具链。

## 3.6 有界缓冲与速率匹配

假设输入平均速率 $r_{in}$ 大于处理速率 $r_{out}$，容量为 N 的缓冲会以约 $r_{in}-r_{out}$ 的速率被占满。若初始为空、速率恒定：

$$
T_{overflow}\approx\frac{N}{r_{in}-r_{out}}.
$$

N=256 字节，输入 12000 B/s、处理 10000 B/s，则约 0.128 秒后溢出。增大缓冲只能延迟持续失配，不能消除它。系统必须降低输入、提高处理能力，或规定丢弃与背压策略。

环形缓冲还要明确满和空的编码方式。若通过 head==tail 表示空，常见实现会保留一个槽位区分满；名义长度 N 与可用容量 N-1 不能混淆。

## 练习与解题提示

1. $f_{tim}=48$ MHz，PSC=47、ARR=1999，更新频率是多少？
2. 事件周期 1 ms，平均 ISR 时间 0.1 ms，能否断言满足实时要求？
3. 为什么加大缓冲不能修复长期输入比处理快的问题？

**提示与答案：** 1. 500 Hz。2. 不能；需最坏延迟、嵌套和处理时间，还要定义截止时间。3. 积压持续增长，任何有限容量最终都会耗尽。
